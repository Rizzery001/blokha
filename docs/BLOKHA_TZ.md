# БЛОХА (BLOKHA) — техническое задание для Claude Code

**Версия:** 1.0 (11 октября 2026)  
**Статус:** согласованный каркас правил семейной настольной игры; вопросы в разделе 12 требуют подтверждения до публикации, но не должны мешать локальному MVP.  
**Исходный материал:** две фотографии физической доски 8×8, передаваемые разработчику вместе с документом.

## 1. Цель и ожидаемый результат

Создать **настоящую работающую браузерную игру** «Блоха» для 2–4 игроков, а не статичный прототип интерфейса. Игроки по очереди бросают один шестигранный кубик, выставляют по четыре фигуры, обходят периметр шахматной доски по часовой стрелке, проходят специальные клетки, выбивают соперников и заполняют свои диагональные финишные зоны. Побеждает первый, занявший все четыре клетки своей диагонали.

Два обязательных режима MVP: **игра нескольких человек за одним устройством** (hot seat) и **приватная онлайн-комната** с кодом/ссылкой. Сначала обеспечить точный и тестируемый игровой движок; затем хороший визуальный интерфейс; затем стабильную онлайн-синхронизацию. Подготовить проект к последующему мобильному выпуску, но не разрабатывать нативные приложения сейчас.

## 2. Доска, система координат и направление

- Доска шахматная, **8 × 8 = 64 клетки**. Координаты стандартные: A–H слева направо, 1–8 снизу вверх при обычном виде сверху (A1 — левый нижний угол).
- Основной игровой путь — **только внешний периметр из 28 уникальных клеток**.
- Все игроки передвигаются **по часовой стрелке**, независимо от начального угла.
- Канонический массив клеток пути (нулевой индекс = A1):

```ts
const PERIMETER = [
  'A1','A2','A3','A4','A5','A6','A7','A8',
  'B8','C8','D8','E8','F8','G8','H8',
  'H7','H6','H5','H4','H3','H2','H1',
  'G1','F1','E1','D1','C1','B1',
] as const;
```

С A1 фигура идёт по A-файлу вверх, по восьмой горизонтали вправо, по H-файлу вниз, по первой горизонтали влево, затем возвращается на A1. Для других углов путь тот же, с циклическим сдвигом начала.

### Четыре старта и четыре частные финишные диагонали

| Старт игрока | Финиш в направлении от угла к центру | Дальняя клетка |
|---|---|---|
| A1 | A1 → B2 → C3 → D4 | D4 |
| H1 | H1 → G2 → F3 → E4 | E4 |
| H8 | H8 → G7 → F6 → E5 | E5 |
| A8 | A8 → B7 → C6 → D5 | D5 |

Финишные клетки внутри доски принадлежат только соответствующему игроку и не являются частью общего периметра. Стартовая угловая клетка каждого игрока **одновременно** является клеткой общего маршрута и первым местом его финишной диагонали. Угол не защищён от выбивания противником — **даже когда собственная фигура уже завершила полный круг**.

## 3. Состав партии и фигуры

- 2–4 игрока, каждый выбирает свой уникальный стартовый угол.
- У каждого игрока **строго 4 фигуры**, все начинают в **резерве вне поля**.
- Шахматная форма (пешки, кони, ладьи, слоны, ферзи, короли) — **исключительно косметика**. Фигуры не ходят по правилам шахмат. Дать наборы с разными формами, персональными акцентными цветами и различимой маркировкой для каждого игрока. Нужен выбор четырёх фигур до старта.
- **На любой клетке может стоять максимум одна фигура**, включая две фигуры одного владельца. Никакого наложения, стекинга, «забора» из нескольких фигур на одной клетке.
- Фигуры, выбитые соперниками, возвращаются в резерв, и их прогресс полностью обнуляется.

## 4. Ходы и кубик

1. В начале обычной очереди активный игрок получает один бросок стандартного кубика (1–6).
2. Чтобы выставить фигуру из резерва на собственную стартовую угловую клетку, нужно выбросить **6**. При шестёрке игрок **выбирает**: вывести из резерва новую фигуру (если допустимо) либо передвинуть любую допустимую свою активную фигуру на 6 клеток.
3. **Каждая шестёрка всегда начисляет +1 дополнительный бросок**. Несколько шестёрок подряд дают несколько дополнительных бросков; лимита и наказания за три шестёрки нет.
4. После броска интерфейс показывает только юридически допустимые фигуры/действия. Игрок выбирает фигуру; система применяет ход и эффект клетки. Если допустимых действий нет, **текущий бросок сгорает**.
5. Если после обработки текущего броска остались дополнительные броски — игрок продолжает кидать, даже если предыдущий бросок сгорел. Если нет — очередь переходит следующему игроку с учётом штрафов.
6. Запрещён произвольный отказ от допустимого броска без отдельного согласования. Если нет легальных действий, списывается только текущий бросок.
7. Броски происходят на сервере в онлайн-режиме; клиент не может подменить выпавшее число или ход.

### Блокировка при ОБЫЧНОМ ходе

При обычном броске кубика **каждая промежуточная клетка обязана быть свободна**: ни через свои, ни через чужие фигуры перепрыгивать нельзя.

- Промежуточная клетка занята своей или чужой фигурой → **данной фигурой ход запрещён**.
- Конечная клетка пуста и путь свободен → перемещение разрешено.
- Конечная клетка занята **чужой** фигурой, путь свободен → перемещение разрешено с **выбиванием** чужой фигуры в резерв.
- Конечная клетка занята **своей** фигурой → перемещение запрещено.

Это правило действует и для обычного продвижения по финишной диагонали.

### Выход из резерва на шестёрке

- Если своя стартовая угловая клетка свободна → новая фигура ставится на неё.
- Если там чужая фигура → новая фигура ставится на угол **с выбиванием** чужой в резерв.
- Если там собственная фигура → вывести туда ещё одну нельзя; вместо этого можно ходить активной фигурой на 6, если такой ход законен.
- Нельзя ставить две фигуры на один угол ни при каких условиях.

## 5. Специальные клетки — точные координаты с физических фотографий

| Координата | Текст на физической доске | Эффект |
|---|---|---|
| **A2** | 5 вперёд | Автоматическое перемещение вперёд на 5 |
| **H5** | 3 вперёд | Автоматическое перемещение вперёд на 3 |
| **H7** | 5 назад | Автоматическое перемещение назад на 5 |
| **D1** | 1 ход пропуск | Штраф −1 к балансу бросков |
| **C8** | 3 хода пропуск | Штраф −3 к балансу бросков |
| **E8** | 1 ход доп. | +1 дополнительный бросок |
| **F1** | 3 хода доп. | +3 дополнительных броска |

Реализовать как **конфигурацию**, а не как константы в UI. Клетка активируется при **попадании на неё как на конечную клетку обычного перемещения**; проход через неё не активирует эффект. Нахождение на бонусе без нового попадания не активирует его повторно.

### Автоперемещение вперёд: 5 и 3

- Промежуточные клетки должны быть свободны.
- Если хотя бы на одной из промежуточных клеток стоит своя или чужая фигура → бонусное перемещение **отменяется**, фигура остаётся на клетке с бонусом.
- Если конечная клетка свободна → фигура передвигается на неё.
- Если конечная клетка занята **чужой** фигурой и весь промежуточный путь свободен → чужая **выбивается**.
- Если конечная клетка занята **своей** фигурой → бонусное перемещение **отменяется**, фигура остаётся на бонусной клетке.

Фактические маршруты:

- A2 «5 вперёд»: A2 → A3 → A4 → A5 → A6 → **A7**.
- H5 «3 вперёд»: H5 → H4 → H3 → **H2**.

### Автоперемещение назад: 5

- Промежуточные клетки **и конечная** должны быть свободны.
- Если любая промежуточная клетка занята, бонус отменяется, фигура остаётся на H7.
- Если конечная клетка занята **любой** фигурой, бонус также отменяется.
- **Назад выбивать нельзя.**

Точный обратный маршрут: H7 → H8 → G8 → F8 → E8 → **D8**.

**Важно:** хотя фигурка проходит через E8 («1 дополнительный ход»), этот бонус не активируется: E8 — промежуточная клетка, фактический финиш — D8. Аналогично при прохождении через любые специальные клетки. На конкретной доске конечные клетки автобонусов (A7, H2, D8) не являются бонусными — цепочки автоматических эффектов не нужны.

## 6. Дополнительные броски и штрафы: взаимозачёт

ЭТО КРИТИЧЕСКОЕ ОТЛИЧИЕ ИГРЫ.

- «1 ход доп.» даёт **сразу +1** бросок.
- «3 хода доп.» даёт **сразу +3** броска.
- Каждая выпавшая **6** даёт **+1** бросок сверх текущего.
- «1 ход пропуск» и «3 хода пропуск» вычитают соответственно **1** или **3** из ещё не использованных дополнительных бросков.
- Если бонусных бросков меньше, чем величина штрафа, излишек становится количеством будущих пропущенных **очередей игрока**, пока другие участники ходят нормально.
- Все бонусы и штрафы суммируются; отрицательный баланс нельзя трактовать как «сначала доиграть бонусы, потом пропускать полный штраф».

**Примеры:**

| Неиспользованные бонусы перед попаданием на штраф | Полученный штраф | Итог |
|---|---|---|
| +2 | −3 | Пропустить 1 будущую свою очередь |
| +1 | −3 | Пропустить 2 очереди |
| +3 | −3 | Баланс 0, очередь заканчивается |
| +5 | −3 | Остаётся 2 дополнительных броска |
| 0 | −1 | Пропустить 1 очередь |

Рекомендуемая модель: `bonusRollsRemaining >= 0` и `skippedTurnsRemaining >= 0`; при начислении штрафа сначала погасить `bonusRollsRemaining`, а оставшуюся величину добавить в `skippedTurnsRemaining`. Либо реализовать эквивалентный подписанный баланс со строгими тестами. При получении бонусных бросков после текущего броска игрок продолжает **сразу**. Каждый использованный дополнительный бросок списывается, даже если все фигуры оказались заблокированы.

**Пример с шестёрками:** есть +3 бонусных броска; первый бонусный бросок = 6 → потратили 1, получили +1, остаётся +3; второй бонусный бросок = 6 → снова +3; третий = 4 → остаётся +2. Если на этих бросках игрок получает «−3», происходит немедленный взаимозачёт с актуальным остатком.

**Пример блокировки:** у игрока осталось +2 броска. Следующий бросок = 4, ходить некем → этот бросок сгорает, остаётся +1; следующий бросок тоже не даёт легального хода → сгорает, баланс 0, очередь переходит сопернику.

Если игрок имеет штраф пропущенных очередей, во время каждой его будущей очереди движок списывает один пропуск **без броска**, а затем передаёт управление следующему участнику. UI показывает количество оставшихся пропусков.

## 7. Полный круг, вход на диагональ и победа

Каждая фигура имеет собственный прогресс, не сводящийся к текущей клетке: `reserve`, `perimeter`, `finish`, `locked`.

Для игрока A1:

- Фигура выставлена на A1: нулевой прогресс по кругу.
- Сделав **28 шагов** по часовой стрелке от A1, фигура возвращается на A1 и получает право пройти внутрь своей диагонали.
- Следующий шаг после полного круга: **B2**, затем **C3**, затем **D4**.
- Чтобы попасть на D4, нужна суммарная длина пути **31 шаг** от первоначальной постановки на A1.
- Фигура может останавливаться на углу после круга и на промежуточных диагональных клетках и продолжать движение в последующие броски.
- Ход разрешён **только при точном достижении** допустимой конечной клетки: нельзя выбросить 5, когда от C3 до D4 остался 1 шаг; бросок не даёт хода этой фигурой.
- Нельзя перескакивать через уже занятые финишные клетки и нельзя заканчивать на своей фигуре.
- Когда фигура доходит до крайней клетки D4, дальше она **никогда не движется** (`locked`). Следующая фактически остаётся на C3, следующая на B2 и последняя на A1. Остальные фигуры на диагонали могут продвигаться вперёд к крайней клетке, если она свободна и путь чист.
- Победа — все четыре **собственные** фигуры одновременно занимают A1, B2, C3 и D4. Аналогично для остальных трёх углов.

**Особое правило угла:** собственная фигура, вернувшаяся на угол после 28 шагов, ещё уязвима для выбивания чужой фигурой, точно попавшей на эту клетку с периметра. После выбивания она возвращается в резерв и теряет весь прогресс. Три внутренние диагональные клетки недоступны чужим фигурам.

Предлагаемая инженерная модель:

- `progress = 0` означает фигура выставлена на старт; `progress = 1..27` — перемещение по периметру; `progress = 28` — вновь на углу, по завершении круга; `progress = 29..31` — B2, C3, D4 относительно игрока A1.
- Для всех игроков `progress` одинаков, меняется только исходный индекс стартовой клетки в цикле PERIMETER и собственный массив диагонали.
- Маппинг `progress === 28` должен давать реальную стартовую угловую клетку, `progress === 29..31` — три следующие клетки персональной диагонали.
- Не допускать превышения `progress = 31` даже при броске шестёрки.
- Учитывать фигуры на промежуточных клетках при проверке попытки пересечь угол и войти в финиш.

## 8. Пользовательский интерфейс и качество дизайна

Цель — качественная **настольная игра онлайн**, приятная на телефоне и компьютере:

- Современная лаконичная, но тёплая визуальная эстетика. Доска шахматная с подписями A–H и 1–8, узнаваемые и явно отмеченные 7 специальных клеток.
- Два сменных оформления: **Classic Wood** (по реальным фотографиям семейной доски) и **Modern** (аккуратный премиальный цифровой стиль).
- Объёмные фишки (допускается 2.5D), выразительная анимация 3D-подобного кубика, лёгкие тени, подсветка активного игрока, доступных фигур и возможного приземления.
- Анимация последовательного движения по клеткам; эффект выбивания и возвращения в резерв; стрелки бонусного движения; уведомления о бонусных бросках/пропусках; анимация победы.
- Действия: «Создать комнату», «Войти по коду», «Играть локально», «Бросить кубик», «Выбрать фигуру», «Новая партия», «Настройки».
- В лобби: 2–4 места, никнеймы, выбор углов, выбор комплектов фигур, хозяин начинает партию.
- После броска показать легальные фигуры; не заставлять пользователя угадывать, почему некоторые недоступны. При невозможности хода вывести понятное сообщение («Все фигуры заблокированы; бросок сгорел»).
- Мобильная адаптация без горизонтальной прокрутки игрового поля, крупные кликабельные элементы, корректное отображение на iPhone/Android, мышью и пальцем.
- Ключевые события отражать в коротком журнале партии.
- Не копировать брендинг/иллюстрации Monopoly, использовать только её как референс уровня полировки.

## 9. Предлагаемая техническая архитектура

- Монорепозиторий **pnpm** (либо эквивалент) `apps/web`, `apps/server`, `packages/game-engine`, `packages/shared`.
- **Web:** React + TypeScript + Vite + Tailwind CSS; доска как SVG или CSS Grid с анимациями. Не подключать громоздкий 3D-движок, если он не нужен для MVP.
- **Backend:** Node.js + TypeScript + Socket.IO / WebSocket, авторитетный сервер.
- **Engine:** чистая детерминированная библиотека без React и Socket.IO: правила и переходы состояния через типизированные команды/события.
- Броски кубика **только на сервере**, `crypto.randomInt(1, 7)`; не доверять присланным клиентом броскам/координатам/состоянию.
- Для каждого действия сервер проверяет игрока, очередь, версию состояния и законность выбранного действия. Нельзя сделать ход за другого игрока, дублировать команду или выполнить действие при потере очереди.
- Комнаты: короткий код/ссылка, guest nickname без регистрации, возможность входа/переподключения по индивидуальному токену, восстановление текущего состояния при обновлении страницы.
- Для MVP допустимо хранение комнат в памяти сервера, но честно предупреждать, что перезапуск сервера удалит партии; подготовить абстракцию `RoomStore` под дальнейшее постоянное хранилище. Не обещать сохранность матчей без реально подключённой базы.
- Настройки комнаты: 2–4 игрока, выбор углов, тема доски. Не создавать настройки, меняющие подтверждённые правила в первой версии.
- Подготовить `.env.example`, команды `dev`, `test`, `build`, README и простую инструкцию выкладки на сервис с постоянными WebSocket-соединениями (например, Railway).

### Минимальные модели

```ts
interface Piece {

  appearance: string;
}

interface PlayerState {

  nickname: string;
  corner: Corner;
  pieces: [Piece, Piece, Piece, Piece];
  bonusRollsRemaining: number;
  skippedTurnsRemaining: number;
}

// Источник истины: server GameState. Состояние должно различать
// «ожидание броска», «выпало число — ждём выбора фигуры»,
// «применение эффектов», «очередь завершена», «победа».
```

Нужны функции/чистые переходы: `getCellForProgress`, `getPathForMove`, `getLegalActions`, `resolveDiceRoll`, `applyPieceMove`, `resolveSpecialCell`, `applyTurnBalance`, `advanceTurn`, `checkVictory`. Разделить **расчёт движения** и **анимацию движения**.

## 10. Приёмочные тесты: реализовать обязательно

1. Без шестёрки фигуру из резерва поставить нельзя; шестёрка позволяет выставить фигуру и даёт дополнительный бросок.
2. При шестёрке можно выбрать перемещение существующей фигуры вместо вывода новой.
3. Шестёрка на старте выбивает стоящую на стартовом углу чужую фигуру; собственная фигура блокирует новую постановку.
4. На клетке физически не может оказаться более одной фигуры.
5. Обычный ход A1 → A5 по броску 4 **заблокирован**, если стоит любая фигура на A3.
6. Если обычный путь свободен, точное попадание на соперника выбивает его.
7. A2 «5 вперёд» переводит на A7, если путь свободен; на A7 можно выбить соперника.
8. A2 «5 вперёд» не срабатывает, если A3, A4, A5 или A6 занята, либо A7 занята своей фигурой.
9. H5 «3 вперёд» ведёт к H2 и подчиняется тем же правилам.
10. H7 «5 назад» ведёт к D8; путь H8, G8, F8, E8, D8 должен быть свободен; никакого выбивания назад.
11. Проход через E8 во время «5 назад» не даёт дополнительный бросок.
12. Прямое обычное попадание на F1 даёт 3 дополнительных броска, на E8 — 1.
13. Каждая шестёрка в серии увеличивает баланс бросков на один без ограничений.
14. «+2 бонусных» затем «−3 пропустить» приводит к 1 пропущенной будущей очереди.
15. «+5 бонусных» затем «−3 пропустить» оставляет 2 дополнительных броска.
16. Заблокированный бросок сгорает, но не уничтожает остальные дополнительные броски.
17. Периметр в правильном порядке: A1 → A2 → … → A8 → B8 → … → H8 → H7 → … → H1 → G1 → … → B1 → A1.
18. После 28 шагов с A1 фигура находится на A1 с признаком полного круга; далее B2 (29), C3 (30), D4 (31).
19. При фигуре на C3 и свободной D4 бросок 1 позволяет закончить движение; бросок 2 (с превышением D4) запрещён.
20. Если D4 занята своей фигурой, другая фигура не может перепрыгнуть её или занять ту же клетку.
21. Враг может выбить фигуру на углу A1 даже после пройденного круга; внутренние B2/C3/D4 недоступны врагам.
22. Победа только при заполнении четырёх конкретных финишных клеток соответствующего игрока.
23. Углы H1/H8/A8 используют корректно повёрнутые маршруты и диагонали.
24. На сервере запрещены чужие команды и повторное применение одного хода.
25. Два или более клиента видят один результат кубика и одинаковое состояние; переподключённый игрок получает актуальное состояние.

Помимо unit tests написать end-to-end smoke test для локальной партии и онлайн-комнаты. Тестировать без мокового UI, который выглядит работающим, но не выполняет правила.

## 11. Порядок выполнения задачи в Claude Code

**Этап 1.** Создать проект, README, структуру типов, конфигурацию поля и чистый GameEngine. Написать тесты маршрута, блокировок, спецклеток и бонусных бросков. Запустить тесты и сообщить результат.

**Этап 2.** Сделать локальную игру hot seat на одном устройстве с реальным движком. Все 2–4 игрока должны иметь возможность завершить партию. Показать скриншот/превью, объяснить управление.

**Этап 3.** Сделать комнаты с WebSocket, авторитетную проверку ходов, повторное подключение и короткие ссылки для приглашений.

**Этап 4.** Довести дизайн: дерево/modern темы, анимации, выбор фигур, удобный мобильный экран.

**Этап 5.** Прогнать unit/e2e, собрать production build, задокументировать деплой и ограничения MVP.

Никогда не выдавать исключительно HTML-концепт за готовую игру. Не утверждать, что онлайн работает, пока не проверено соединение хотя бы двух клиентов. Публикацию в интернете делать только по просьбе владельца и при наличии подходящей инфраструктуры/доступа.

## 12. Точки для окончательного подтверждения, если всплывут при реализации

Не выдумывать новые семейные правила. Если появляется неоднозначность — отметить её, сделать минимальную конфигурируемую реализацию и запросить подтверждение:

1. **Шестёрка при абсолютно недоступном ходе:** в описании зафиксировано, что каждая шестёрка даёт +1 дополнительный бросок — использовать именно это правило, даже если её перемещение сгорело, до возможного изменения владельцем.
2. **Попадание на занятый угол при входе на финиш:** обычные правила точного попадания, блокировки промежуточных клеток и выбивания действуют и на углу. Не вводить иммунитет.
3. **Четыре стартовых угла и очередность игроков:** выбирать свободный угол в лобби и следовать порядку игроков в лобби; не привязывать очередность к геометрическим углам без запроса.
4. **Оставление фигуры на промежуточной диагональной клетке:** игрок вправе двигать её дальше до крайней свободной клетки; находящиеся ближе к углу фигуры могут в итоге перестать иметь легальные ходы из-за уже занятых финишных клеток. Не удалять такие фигуры с доски.
5. **Реакция на сетевой дисконнект:** для первой версии пауза/ожидание игрока + переподключение; не выдумывать автоматические ходы за отсутствующего игрока.

## 13. Критерий готовности MVP

Реальная партия от выставления фигур до победы работает в браузере, независимо от выбранного угла игрока, строго соблюдает все пункты выше, покрыта автотестами, имеет локальный режим и работающую приватную онлайн-комнату. Для запуска требуется только выполнить задокументированные команды установки и запуска; отсутствующие внешние сервисы и ограничения названы прямо.
