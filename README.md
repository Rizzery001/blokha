# BLOKHA — «Блоха»

Браузерная версия семейной настольной игры «Блоха» для 2–4 игроков: шахматная доска 8×8, один кубик,
по четыре фигуры у каждого, движение по периметру по часовой стрелке, семь специальных клеток,
выбивание соперников и четыре частные финишные диагонали. Полные правила — в [docs/BLOKHA_TZ.md](docs/BLOKHA_TZ.md).

## Структура

```
packages/game-engine   чистый детерминированный движок правил (TypeScript, без React/сокетов) + тесты
apps/web               React + Vite + Tailwind: локальная игра (hot seat), затем онлайн-комнаты
apps/server            (Этап 3) авторитетный сервер комнат, броски кубика только на сервере
docs/                  ТЗ, фотографии физической доски
```

Конфигурация доски (периметр, финишные диагонали, спецклетки, правила) — `packages/game-engine/src/config/board.json`.

## Команды

```bash
pnpm install
pnpm test          # тесты движка и сервера (vitest), включая два Socket.IO-клиента
pnpm typecheck
pnpm dev           # сервер комнат :3001 + web-клиент http://localhost:5173 (vite проксирует /socket.io)
pnpm build         # engine/shared typecheck, web → apps/web/dist, server → apps/server/dist
pnpm start         # продакшен: сервер раздаёт собранный клиент и WebSocket на $PORT
pnpm e2e           # Playwright: локальная партия, партия с роботами, онлайн-комната (нужен pnpm dev)
```

## Режимы

- **Локально / с роботом** — все игроки за одним устройством; любое место можно отдать роботу
  (кнопка «🤖 Робот» рядом с именем). Можно играть одному против 1–3 роботов.
- **Онлайн-комната** — «Создать комнату» выдаёт код из 6 символов и ссылку вида `https://…/?room=КОД`.
  Друзья входят по ссылке или коду, хозяин может добавить роботов на свободные места и начинает партию.
  Кубик бросает только сервер; команды проверяются по токену игрока, очереди и версии состояния.
  После перезагрузки страницы игрок возвращается в свою партию по сохранённому токену; пока кто-то
  отключён, остальные видят баннер «Ждём игрока» (автоходов за отсутствующего нет).

## Оформление и анимации

- Темы **Classic Wood** (текстура берёзы и морёного дерева, трафаретные подписи спецклеток, как на
  семейной доске) и **Modern**. Переключение в игре и на главном экране, выбор запоминается.
- Кубик: 3D-куб падает на доску, кувыркается, приземляется с подсветкой; маленький кубик в панели
  показывает последнее значение.
- Фигуры: объёмные силуэты (пешка, конь, ладья, слон, ферзь, король), прыгают по каждой клетке пути.
  Золотая галочка на фигуре означает «полный круг пройден»: такая фигура может идти на диагональ.
  Выбитая фигура вылетает с доски и возвращается в резерв.
- Стрелки бонусных и штрафных авто-перемещений, всплывающие уведомления (шестёрка, бонусные броски,
  пропуски, выбивание, сгоревший бросок), конфетти при победе. `prefers-reduced-motion` отключает анимации.

## Робот

`chooseBotAction` в движке: оценивает только легальные действия, рассчитанные правилами
(выбивание, вход на финиш, бонусные клетки, безопасность после хода, штрафные клетки). Правила не меняет.

## Локальная игра (hot seat)

«Играть локально» → выбрать число игроков (2–4), ники, углы, наборы фигур и цвета → «Начать партию».

- **Бросить** — бросок кубика за активного игрока (подсвечен жёлтой рамкой).
- После броска подсвечиваются только легальные фигуры: на доске (пульсирующее кольцо) и в резерве
  в панели игрока (при шестёрке). Клик по фигуре выполняет ход; голубой рамкой отмечены клетки назначения.
- Если ходов нет, журнал сообщает «Все фигуры заблокированы; бросок сгорел», а рядом со статусом
  показывается, почему каждая фигура недоступна.
- Бонусные броски и пропуски очередей видны в панели игрока; авто-перемещения и выбивания анимируются
  по клеткам и попадают в журнал. `?fast` в адресе убирает задержки анимации (для e2e).
- Тема переключается в игре и на главном экране: Classic Wood / Modern.

## Движок: модель состояния

- `progress` фигуры: `null` — резерв; `0` — только что выставлена на свой угол; `1..27` — периметр;
  `28` — снова на углу после полного круга; `29..31` — три внутренние клетки диагонали (`31` — `locked`).
- Клетка вычисляется из прогресса и угла игрока: `getCellForProgress(config, corner, progress)`.
- Единственная точка изменения состояния — `applyCommand(state, command)` с командами `roll` и `chooseAction`.
  Значение кубика передаётся снаружи (в онлайне — сервер, локально — Web Crypto).
- Баланс бросков: `bonusRollsRemaining >= 0`, `skippedTurnsRemaining >= 0`; штраф сначала гасит
  неиспользованные бонусные броски, остаток становится пропусками очередей (`applyTurnBalance`).
- Бонусный бросок списывается в момент броска; очередь переходит, когда баланс бонусов равен нулю.

## Уточнения правил, подтверждённые владельцем

1. **«5 назад» для игрока со стартом H8.** H7 — его первая клетка; откат на 5 уводит фигуру на D8,
   *за* собственный старт. Движок хранит отрицательный прогресс (−4): фигура проходит 4 клетки до H8
   и затем весь круг заново. Подтверждено.
2. **Победа** засчитывается, только когда все четыре фигуры стоят на финишных клетках *после полного
   круга* (прогресс 28..31). Свежевыставленная фигура на углу не считается. Подтверждено.
3. Шестёрка, чей ход сгорел, всё равно даёт +1 бросок (п. 12.1 ТЗ).

## Деплой (Railway или любой хост с постоянными WebSocket)

Один сервис из `Dockerfile` в корне: сервер Express + Socket.IO раздаёт собранный web-клиент и
WebSocket на `$PORT`, health-check `/health`. Переменные: `PORT` (ставит Railway), опционально `BOT_DELAY_MS`.
`railway.json` уже настроен; достаточно подключить репозиторий к проекту Railway.

**Ограничение MVP:** комнаты хранятся в памяти процесса (`InMemoryRoomStore`). Перезапуск или
редеплой сервера удаляет все партии; клиенты получат сообщение и вернутся на главный экран.
Для сохранности нужна реализация `RoomStore` поверх БД — интерфейс готов, база не подключена.
